# Srijan Saha — engineering portfolio

A static site. No build step, no dependencies, no framework. Three files do the
work: one for content, one for layout, one for style.

```
portfolio/
├─ index.html              home page
├─ project.html            renders any project from ?id=
├─ content/
│  └─ projects.js          ← everything you write lives here
└─ assets/
   ├─ css/site.css         design tokens at the top of the file
   ├─ js/render.js         turns the data into pages
   └─ media/               your videos and photos
```

## Run it

From inside the `portfolio` directory:

```bash
python3 -m http.server 5173
```

Then open <http://localhost:5173>.

Any static server works — `npx serve`, `php -S localhost:5173`, whatever you
have. Opening `index.html` directly from the file manager also works, since
nothing here uses `fetch`, but the local server is closer to how it will behave
once it's hosted.

To stop the server, press `Ctrl+C`.

## LunarRL: the reinforcement-learning project

`project.html?id=lunar-rl` is the one project page whose results are generated by
code. Everything about it lives in three places:

```
lunar-rl/                         Python source: train, evaluate, export (own README)
assets/data/lunarrl-results.js    generated data the page draws (do not edit by hand)
assets/js/lunarrl-viz.js          draws the charts as plain SVG, no library
assets/media/lunar-rl-*.mp4|jpg   generated same-seed replays (trained and random)
```

**How it works.** A PPO agent (Stable-Baselines3) learns to land Gymnasium's
`LunarLander-v3` from its shaped reward. `evaluate.py` then plays the trained agent
and a random policy on the same 100 held-out seeds. `export_results.py` writes the
replays and `assets/data/lunarrl-results.js`. The page loads that file with a plain
`<script>` tag, so it needs no server, no `fetch`, and no Python on the host. The
written sections (explainer, caveats, what I built) are ordinary fields in
`content/projects.js`; the project uses two optional fields, `explainer` and
`dataviz`, which other projects can ignore.

**Reproduce training or replace the results with your own run** (macOS, Python 3.11):

```bash
cd lunar-rl
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python train.py --run-name ppo_baseline --seed 0
python evaluate.py --run-name ppo_baseline --episodes 100
python export_results.py          # add --extra-runs / --experiment if you trained them
```

`export_results.py` overwrites `assets/data/lunarrl-results.js` and
`assets/media/lunar-rl-{ppo,random}.{mp4,jpg}`. Refresh the page and every number,
chart and clip updates. Numbers that also appear in prose in `content/projects.js`
(the LunarRL `summary`, `statusLine`, `built` and `caveats`) are written by hand, so
after your own run update those to match the new `lunar-rl/results/ppo_baseline/eval_summary.json`.
See `lunar-rl/README.md` for seeds, the reward and the experiment, and
`lunar-rl/LEARN-LUNARRL.md` for a one-hour walkthrough.

**Weight.** The page adds about 10 KB of data, 10 KB of script and two short MP4s
that load only when played (`preload="metadata"`, no autoplay, no audio track).

## Add a project

Everything is in `content/projects.js`. Copy an existing project block, paste it
into the `projects` array, and change the fields. Order in the array is the
order on the page.

```js
{
  id: "my-new-project",        // unique, lowercase, hyphens — becomes the URL
  title: "What it is",
  kicker: "One line under the title",
  status: "wip",               // key from the `statuses` object above
  statusLine: "Where it actually stands, in one sentence.",
  year: "2026",
  tags: ["Computer vision", "Hardware"],

  summary: "Two or three sentences. Shown on the home page and at the top.",

  built: [
    "One bullet per thing you actually made."
  ],

  hardest: {
    title: "The problem, as a sentence",
    body: "What made it hard, what you tried, what you learned."
  },

  next: [
    "What you're doing next."
  ],

  caveats: [],                 // anything a reader must know before trusting it

  evidence: [
    { type: "video", src: "", caption: "What this clip shows." },
    { type: "image", src: "", caption: "What this picture shows." }
  ],

  links: [
    { label: "Code", url: "" }
  ]
}
```

Save the file and refresh the browser. That's the whole workflow.

### Status keys

Defined at the top of `content/projects.js`. Each has a glyph so a plan never
looks like a finished build:

| key            | shows as            | glyph            |
|----------------|---------------------|------------------|
| `demonstrated` | Working demo        | filled square    |
| `built`        | Built and running   | filled square    |
| `wip`          | In progress         | half-filled      |
| `simulation`   | Simulation only     | hatched          |
| `planned`      | Planned             | dashed outline   |

Add your own by adding a key to the `statuses` object.

### Empty fields are fine

- A link with an empty `url` renders as a visible "add link" placeholder instead
  of a broken link.
- A media slot with an empty `src` renders as a labelled empty frame showing the
  filename it expects.
- `caveats: []` hides the notice box entirely.

This is deliberate — the gaps should be obvious to you and should read as
honest to a visitor, rather than silently disappearing.

## Change the design

Design tokens are the first 40 lines of `assets/css/site.css`: colours, type
families, page width. Change them there and everything follows. Dark mode is
defined in the same place and follows the reader's system setting.

The palette is a pale instrument grey (`--paper`) with deep green-black ink and
a single signal lime (`--signal`) used only for status glyphs and keyboard
focus. Type is Archivo for headings and data, Source Serif 4 for prose. The
corner brackets around the hero are a tracking reticle; they animate once on
load and are disabled for anyone who's set reduced motion.

## Things to keep out of this repo

The site is built to be published, so treat everything in it as public:

- No school name, home address, street, or phone number
- No photos or video showing your house's interior layout
- No invented results, awards, testimonials or test numbers — if a number isn't
  measured yet, leave the `TODO` in place until it is

## Deploy

This is a plain static folder, so anything that serves static files will host it
as-is (Netlify steps are at the end of this file). `lunar-rl/` is source code for
the LunarRL project; the page does not need it at runtime, but shipping it is
harmless and lets visitors read the code. If you would rather not publish it,
delete `lunar-rl/` from the copy you deploy; the page keeps working because it
only reads `assets/`. Never deploy a `.venv/` folder.

## The "Beyond engineering" section

Lives in `content/projects.js` under `beyond`, below the `projects` array. It has
a `lead` (the intro paragraphs) and three `strands` — music, martial arts, and
markets/research.

### Adding photos and video

**This section behaves differently from the project pages on purpose.** On a
project page an empty media slot renders a visible dashed "drop zone". In
*Beyond engineering*, a media entry whose `src` is empty renders **nothing at
all** — no empty frames, no placeholder text. The captions are already written;
the figures simply appear once you point them at a file.

To add one:

1. Drop the file into `assets/media/`.
2. Find the matching entry in the strand's `media: [ ... ]` array.
3. Set its `src` (and `poster` for video).

Suggested filenames — these are only conventions, any name works:

| Strand | Entry | File to add |
|---|---|---|
| Music | Jazzinators, leading the group | `music-jazzinators-1.mp4` + `.jpg` poster |
| Music | SJYS Jazz Ensemble | `music-sjys-jazz-1.jpg` |
| Music | SJYS Philharmonic | `music-sjys-phil-1.jpg` |
| Music | Downtown Pleasanton set | `music-pleasanton-1.mp4` + `.jpg` poster |
| Martial arts | Training at West Coast Martial Arts | `martial-arts-1.jpg` |

Example, once the file is in place:

```js
{ type: "video",
  src: "assets/media/music-jazzinators-1.mp4",
  poster: "assets/media/music-jazzinators-1.jpg",
  caption: "East Bay Traditional Jazz Society Jazzinators — drums, and leading the group." }
```

Edit the `caption` freely — adding the venue and roughly when it was is worth
doing, since the caption is what explains the event and your role.

**Poster frames.** A video with no `poster` shows a black rectangle until it
loads. To pull one out of the clip:

```bash
ffmpeg -ss 2 -i assets/media/music-jazzinators-1.mp4 -frames:v 1 -q:v 3 \
       assets/media/music-jazzinators-1.jpg
```

**Keep the files small.** Aim for under ~4 MB per clip so the page stays quick:

```bash
ffmpeg -i raw.mov -vf "scale=1280:-2" -c:v libx264 -crf 28 -preset slow \
       -c:a aac -b:a 96k assets/media/music-jazzinators-1.mp4
```

### Adding a new strand

Append an object to `beyond.strands`. Only `id`, `eyebrow`, `title`, `lede` and
`character` are required; every other key is optional and is skipped when absent.

```js
{
  id: "photography",
  character: "markets",      // reuses that strand's visual treatment
  eyebrow: "Photography",
  title: "...",
  lede: "...",
  body: [ "paragraph", "paragraph" ],
  pull: "an optional pull quote",
  figures: [ { value: "6", label: "years" } ],
  rosterTitle: "Where", roster: [ { role: "", org: "", note: "" } ],
  media: [ { type: "image", src: "", caption: "" } ]
}
```

`character` picks the visual treatment and must be one of:

- `music` — panelled background, two-column prose, the 16-tick beat motif
- `martial` — centred, austere, lots of air, the belt motif
- `markets` — document character, supports `featured` (a paper) and `also`

### Scroll animations

Handled by `reveals()` in `assets/js/render.js`. Anything with `class="reveal"`
fades up as it enters the viewport. The script only adds the `js-reveal` class
when it is actually going to animate, so with JavaScript off — or when the
visitor has **prefers-reduced-motion** set — nothing is ever hidden and the page
reads normally.

### 3D scenes (Tello and drumsticks)

Two scroll-driven Three.js scenes, both progressive enhancements. Everything is
vendored under `assets/vendor/`, so there is no CDN, bundler or build step.

| Library | Version | Licence |
|---|---|---|
| three | r186.1 | MIT |
| GSAP + ScrollTrigger | 3.15.0 | GSAP standard "no charge" licence |

Code lives in `assets/js/scenes/` (`boot.js` lazy-loads, `core.js` is shared,
`tello.js`, `drumsticks.js`). Each scene is a pure function of scroll progress,
so scrolling back reverses it exactly.

**Fallbacks.** No WebGL2 or an import-map failure gives the plain static layout
(`is-static`). `prefers-reduced-motion` gives one still frame and hides the
sound button (`is-still`).

**Tello.** The model is built in code (stylised, not a scan). No freely
downloadable Tello was reachable from the build environment. A good candidate is
"Dji Tello" by Temoor on Sketchfab (CC BY 4.0, about 66k triangles, needs a free
login to download). To use it: export a GLB, put it in `assets/models/`, set
`model: "assets/models/tello.glb"` in the Tello `scene` block in
`content/projects.js`, and keep the attribution in `assets/models/CREDITS.md`.
If the file fails to load, the built-in drone is used. The animated sequence is
labelled "Illustration. Not to scale, not flight data."; the recorded video and
results below it carry a separate "Recorded" tag.

**Drumming film (music strand).** One pinned scene: a pair of Vic Firth American Classic 5A
sticks and a 14" snare, built in code (`drumkit.js` models, `drumsticks.js` choreography). The headline,
scholarship line and message come from the strand's `title` and `scene.film`; the ensemble chart is
the `roster` rows marked `chart: true`; the quote and closing line are the strand's `pull` and
`lede`. Stroke feel is tuned at the top of `drumsticks.js` (`TF`, `E`, `ACCENT`, `THETA`, `N`). The
stroke is a wrist-driven pendulum (accelerating fall, impact, damped rebound, wrist lift), not a
keyframe curve. If your sticks are
not 5A, change `model` in the music `scene` block. Audio is a synthesised snare created only after the
visitor presses the sound button; it is off by default.

**Black belt (between music and martial arts).** `belt.js`: a ribbon with thickness, black twill
with seven stitch rows, folds from half-twists, and the profile name in raised gold satin stitch.
The reflection text is `scene.reflection` on the martial-arts strand and uses only that strand's
existing wording.

**Tello camera.** `tello.js` exports `_seq` so the camera path can be sampled without scrolling.
A scroll-position check should show no camera step above about 0.8 units and no pitch step above
0.3 degrees anywhere on the path.

## Publishing to Netlify

Drag the **whole `portfolio` folder** onto the Netlify deploy area, not a zip of
loose files and not the files individually. The folder structure has to survive
the upload, because every media reference is a relative path like
`assets/media/tello-person-following-1.mp4`. If `assets/media/` doesn't exist on
the deploy, the videos silently fail to load while the rest of the page looks fine.

To check a live deploy, open the site, press F12, go to the **Network** tab and
reload. A failing video shows as a red 404 row, and the URL in that row tells you
where the browser looked versus where the file actually ended up.
